# Работа с контурами

В приложении откройте «Как работать» для сценариев по ролям. В «Операциях» видны фоновые задания, ссылки на merge request, pipeline и журналы.

| Сценарий | Порядок действий |
| --- | --- |
| Обычный релиз | Слейте изменения в `dev`, проверьте тестовый контур, создайте релиз на стейдже и подтвердите перенос в прод |
| Хотфикс | Создайте ветку от прода, сохраните правки с повышением версии, запустите «Hotfix в прод», затем выполните обратный перенос из `main` в `dev` |
| Откат | Выберите предыдущую опубликованную версию на странице содержимого. Проверьте итоговую версию после слияния и CI |
| Типы | Создайте новую запись на тесте, проверьте порядок и сравнение метаданных, выполните перенос на следующий контур |
| Миграция | Выберите источник, приёмник и объём данных, пройдите проверку, подтвердите запуск и проверьте журнал |

Для отчётов и автоматизаций шаги зависят от схемы контуров. Приложение показывает доступные действия по состоянию веток и правам пользователя. [Подробное описание выпуска и отката](../proadmin/README.md).

Импорт `.dbp` заменяет данные базы-приёмника на тесте или стейдже. Укажите файловый архив вместе с базой, если после импорта документы должны открываться в Pilot. [Сценарии миграции и ограничения](../proadmin/migration/README.md).
