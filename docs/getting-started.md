# Быстрый старт на Windows

Для запуска без Docker используйте [Windows Portable](https://pilotopentools.github.io/PilotProAdmin/windows-portable.html).

1. Установите и запустите [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/) на компьютере x64. Используйте режим Linux containers. В PowerShell команда `docker info` должна показывать сведения о сервере Docker.
2. Скачайте `PilotProAdmin-vX.Y.Z-lite.zip` со [страницы релизов](https://github.com/PilotOpenTools/PilotProAdmin/releases) и сверьте SHA-256 архива с `SHA256SUMS.txt` через `Get-FileHash`. Распакуйте его **в постоянное надёжное место**, например `D:\PilotProAdmin`, а не в «Загрузки», на рабочий стол или во временную папку. Внутри два файла: `README.md` и `install.ps1`.

   > [!WARNING]
   > Рядом с `install.ps1` установщик создаёт [папку установки](#папка-установки) `PilotProAdmin-install`. В ней хранятся не только настройки, но и сами данные стенда: базы PostgreSQL, базы и лицензии Pilot, данные админки. После установки эту папку **нельзя удалять, переносить и переименовывать**. Удалите её, и вместе с ней пропадут базы, а перенести стенд на другую машину будет уже не из чего. Защищает от этого только [резервная копия](#резервные-копии) на другом диске.
3. Откройте PowerShell в распакованной папке и выполните:

   ```powershell
   .\install.ps1
   ```

   Если Windows заблокировала загруженный скрипт, после проверки архива выполните `Unblock-File -LiteralPath .\install.ps1`.
4. Ответьте на вопросы установщика. Если порт занят, нажмите Enter, чтобы принять предложенный свободный порт, или укажите свой. Установщик запускает PilotProAdmin и PilotMigration одной версии и выводит адреса сервисов.
5. Откройте адрес админки из вывода скрипта. В мастере первого входа проверьте адрес GitLab и введите [ключ установки](#ключ-установки). Войдите через GitLab в браузере или с Personal Access Token GitLab с правом `api`. Кнопка входа через браузер есть, если в `.env` заданы `GITLAB_OAUTH_CLIENT_ID` и `GITLAB_OAUTH_CLIENT_SECRET`. Установщик задаёт их сам при установке из резервной копии, а также когда ставит новый GitLab на этой машине: в этом случае он и создаёт OAuth-приложение в GitLab. Для существующего GitLab создайте приложение вручную (Admin → Applications, scope `api`, Redirect URI `http://localhost:<порт админки>/GitLab/Callback`) и пропишите его ID и секрет в `.env`. Затем проверьте адреса контуров Pilot, задайте служебные учётные записи для выкладки из GitLab CI, проверьте адрес Grafana и укажите группы и проекты GitLab.

## На Linux

Тот же `install.ps1` работает на Linux x64 с Docker Engine (без Docker Desktop):

1. Установите Docker Engine с плагином Compose и [PowerShell 7](https://learn.microsoft.com/powershell/scripting/install/install-ubuntu) (`pwsh`). Команда `docker info` должна работать от root.
2. Распакуйте архив в постоянную папку на диске этой машины (например `/opt/pilotproadmin`, не в `/tmp` и не в домашние «Загрузки») и запустите установку от root. Созданную рядом папку `PilotProAdmin-install` после установки не удаляйте и не переносите: в ней данные стенда (см. [Папка установки](#папка-установки)):

   ```bash
   sudo pwsh ./install.ps1
   ```

   root нужен, чтобы передать папки данных пользователям контейнеров (админка и миграция работают под UID 1654, Grafana под 472). `.env` и папки с секретами получают права `600`/`700`. Docker должен быть локальным (unix-сокет): папки данных монтируются с диска этой машины.
3. Дальше всё как на Windows. Ключ установки показывает команда `sed -n 's/^ADMIN_SETUP_KEY=//p' PilotProAdmin-install/.env`.

## Ключ установки

Ключ установки защищает мастер первого входа: пока админка не настроена, без ключа нельзя ни подключить GitLab, ни задать адреса Pilot. Установщик создаёт ключ сам и в конце пишет, где он лежит: строка `Ключ первого входа: ADMIN_SETUP_KEY в …\.env`.

Ключ хранится в переменной `ADMIN_SETUP_KEY` файла `.env` в папке установки (`PilotProAdmin-install` или выбранной через `-InstallDirectory`). Показать его:

```powershell
Select-String -LiteralPath .\PilotProAdmin-install\.env -Pattern '^ADMIN_SETUP_KEY=' | ForEach-Object { $_.Line.Substring(16) }
```

- Ключ нужен один раз, в поле «Ключ установки» мастера. После завершения мастера админка его больше не спрашивает, дальше вход идёт через GitLab.
- Мастер появляется и после установки из резервной копии: на новой машине снова введите ключ из нового `.env` и войдите через GitLab в браузере или токеном. Адреса Pilot, Grafana и группы GitLab мастер подставит из восстановленных настроек.
- Повторный запуск установщика ключ не меняет.
- Если мастер пишет «Первая настройка закрыта» (ключ в `.env` пуст), задайте `ADMIN_SETUP_KEY` любой длинной случайной строкой и перезапустите админку из папки установки: `docker compose up -d proadmin`.
- В `.env` лежат и остальные пароли стенда: не пересылайте файл целиком, передавайте только ключ.

## Откуда взять образы

Lite скачивает PilotProAdmin и PilotMigration из GHCR. Вариант `PilotProAdmin-vX.Y.Z-offline.zip` — тот же lite, но архив обоих образов уже лежит рядом с `install.ps1`: распакуйте его и запустите `install.ps1` как обычно, за этими образами установка в GHCR не пойдёт. Можно и по отдельности: скачайте `PilotProAdmin-vX.Y.Z-linux-amd64-images.tar.gz` и проверьте его по `SHA256SUMS-CONTAINERS.txt`. Положите архив рядом с `install.ps1` или передайте полный путь:

```powershell
.\install.ps1 -ImageArchive 'D:\Downloads\PilotProAdmin-vX.Y.Z-linux-amd64-images.tar.gz'
```

Архив содержит оба приложения. Для локального GitLab, статистики и серверов Pilot нужны доступ к их реестрам и зависимости сборщиков либо заранее подготовленные образы. Как перенести остальные образы на машину без интернета, описано в [установке стенда, раздел 5](https://pilotopentools.github.io/PilotProAdmin/stack/Install/docs/installation.html#5-установка-без-интернета).

## Чистая установка

- Для GitLab выберите существующий экземпляр или установку на этой машине. Для нового GitLab начальный пароль `root` находится в `GITLAB_ROOT_PASSWORD` в `.env`, а вход в админку через GitLab в браузере настраивается сам: кнопка «Войти через GitLab в браузере» есть уже в мастере первого входа. Создайте токен с правом `api` и группы для нужных типов проектов. Если вход выполняет пользователь без прав администратора GitLab, у него должен быть доступ хотя бы к одной из групп, указанных в мастере.
- Для статистики можно подключить Grafana, развернуть локальную Grafana со сборщиками или настроить позже. Локальные сборщики в этой схеме используют PostgreSQL рабочего контура Pilot.
- Для каждого контура Pilot (тест, стейдж, прод) можно подключить существующий сервер, развернуть локальный Pilot-Server с PostgreSQL и RustFS или отложить настройку. Для скачивания образа Pilot может потребоваться доступ к реестру поставщика. Свой образ можно указать через `-PilotImage`. Для локального сервера установка спросит, загрузить ли базу: см. [База Pilot из файлов](#база-pilot-из-файлов). Лицензию Pilot установите в любом случае. [Установка Pilot-Server](https://pilotopentools.github.io/PilotProAdmin/stack/Install/docs/installation.html).
- **Общие настройки Pilot на каждом сервере.** Модули PilotOpenTools (Pilot.ClientSdk, Reports) можно поставить на серверы Pilot, но их настройки хранятся в базе каждого сервера, и установка их не задаёт. На каждом сервере (prod, test, stage) войдите в клиент Pilot администратором, откройте «Сервис / Настройки / Общие настройки» и заполните разделы «PilotOpenTools отправка статистики» (адрес сборщика статистики) и «PilotOpenTools отчёты (GitLab)» (сервер и группа GitLab с отчётами, Application ID). Готовые значения установка печатает в конце, Application ID для отчётов — `REPORTS_GITLAB_OAUTH_CLIENT_ID` в `.env` (для нового GitLab приложение создаётся само, для существующего создайте его вручную: не confidential, scope `api`, Redirect URI `http://127.0.0.1:7890/callback`). [Подробно](https://pilotopentools.github.io/PilotProAdmin/stack/Install/docs/installation.html).
- Учётные записи для выкладки модулей из CI можно изменить в разделе «Настройки». Для работы CI также нужны ключи выкладки в переменных групп GitLab. При подключении внешнего Pilot доступ к PostgreSQL и архивам для PilotMigration настраивается отдельно. [Настройка стека и интеграций](https://pilotopentools.github.io/PilotProAdmin/stack/Install/docs/installation.html).

### База Pilot из файлов

Новый Pilot-Server ставится без баз. Для каждого контура, который ставится на этой машине, установка спросит:

```text
База Pilot prod. 1 — пустой сервер, 2 — загрузить из файловой базы (.dbp)
```

Ответ `2` делает базу `pilot-ice_ru` из файловой базы Pilot. Укажите **папку базы** — ту, где лежат `base.dbp`, `base.messages.dbp`, `base.journal.dbp` и папка `FileArchive`:

```text
D:\Databases\pilot-ice_ru
D:\Databases\pilot-ice_ru\base.dbp            (путь к самому файлу тоже подойдёт)
D:\Databases.zip\Databases\pilot-ice_ru       (папка внутри .zip, распаковывать не нужно)
```

Если в указанном месте несколько баз (например, весь `Databases.zip`), установка остановится и перечислит их, чтобы вы выбрали одну. Для следующего контура достаточно нажать Enter — подставится тот же путь.

Подключиться к серверу в Pilot-myAdmin: адрес `localhost:5546` (прод), `localhost:5547` (тест) или `localhost:5549` (стейдж) — без порта клиент идёт на 5545, где сервера нет. Логин `admin` (`PILOT_ADMIN_LOGIN`), пароль — `PILOT_ADMIN_PASSWORD` в `.env` папки установки.

Что получится: база `pilot-ice_ru` на PostgreSQL контура, файлы — в его RustFS, у каждого контура свой идентификатор базы. Исходные файлы не меняются. Адрес контура в админке сразу указывает на эту базу. При завершении мастера админка заводит в ней служебного пользователя `admin` с паролем `PILOT_ADMIN_PASSWORD`: под ним выкладываются модули и отчёты. Пользователь получает должность в отдельном подразделении `PilotProAdmin` и занимает одну лицензию. Ответ `1` оставляет сервер пустым: базу тогда подключают вручную. [Подробнее](https://pilotopentools.github.io/PilotProAdmin/stack/Install/docs/installation.html)

## Установка из резервной копии

На исходной машине откройте «Миграция → Подготовить перенос данных» в админке. Скачайте комплект, распакуйте его рядом с доступным Docker Desktop и запустите `prepare-transfer.ps1` по инструкции из комплекта. Скрипт напечатает путь к папке с `manifest.json`.

Выберите восстановление и укажите каталог полной резервной копии с `manifest.json`, либо передайте его при запуске:

```powershell
.\install.ps1 -Backup 'D:\Backup\2026-11-18_0300' -InstallDirectory 'D:\PilotProAdmin'
```

Для восстановления выберите новый каталог установки. Скрипт поднимает локальные GitLab, Grafana со сборщиками и три контура Pilot вместе с PostgreSQL и RustFS. Он берёт версию и редакцию GitLab из имени штатного архива резервной копии. [Требования GitLab к восстановлению](https://docs.gitlab.com/administration/backup_restore/restore_gitlab/). После установки откройте админку и пройдите мастер первого входа с [ключом установки](#ключ-установки) из нового `.env`.

## Папка установки

Папка установки — это `PilotProAdmin-install` рядом с `install.ps1` или каталог, выбранный через `-InstallDirectory`. Это и есть стенд, а не только его конфигурация:

| Что | Где |
| --- | --- |
| Compose и скрипты запуска | `docker-compose.yml`, `install-stack.ps1` |
| Пароли, ключи и адреса стенда | `.env` |
| Базы PostgreSQL контуров | `data\<контур>\postgres` |
| Базы, лицензии и настройки Pilot-Server | `data\<контур>\databases`, `license`, `server-settings` |
| Настройки и журнал админки | `data\services\proadmin` |

Часть данных Docker хранит в своих томах: файловые архивы Pilot (RustFS), вложения GitLab и мониторинг. Без папки установки эти тома бесполезны.

Правила:

- **Не удаляйте, не переносите и не переименовывайте** папку установки, пока стенд работает или может понадобиться. Контейнеры пишут данные прямо в неё.
- Не держите её в «Загрузках», на рабочем столе, во временной папке или в каталоге, который синхронизируется с облаком (OneDrive и т. п.).
- Нужно перенести стенд в другую папку или на другую машину — сделайте копию через «Миграция → Подготовить перенос данных» и установите из неё (`-Backup`) в новый каталог.
- При обновлении распакуйте новый lite в любую папку и запустите установщик с тем же `-InstallDirectory`. Старый распакованный lite после этого можно удалить, папку установки — нет.

## Резервные копии

Папка установки — единственное место, где живут данные стенда. Регулярно снимайте копию на другой диск или сервер: «Миграция → Подготовить перенос данных» даёт комплект со скриптом, он же подходит для плановой копии. Без копии случайное удаление папки или отказ диска означает потерю баз. Для переноса кластера используйте [инструкцию по кластерной установке](https://pilotopentools.github.io/PilotProAdmin/stack/Install/docs/cluster-installation.html).
