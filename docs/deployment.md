# Развёртывание

PilotProAdmin и PilotMigration можно запустить отдельно от Pilot-Server, GitLab, PostgreSQL и S3. Выберите состав установки по инфраструктуре, которую уже обслуживает ваша команда.

| Вариант | Что запускать |
| --- | --- |
| Есть монолитный Pilot-Server | Установите админку, при необходимости добавьте сервис миграции. Укажите адрес действующего Pilot |
| Есть кластер Pilot-Server | Укажите адрес балансировщика. Для миграции предоставьте доступ к PostgreSQL кластера и файловому архиву |
| Нужен новый Pilot-Server | Установочный комплект разворачивает монолитный Pilot для выбранных контуров |
| Нужен кластер Pilot-Server | Установите контур и переведите его в кластер по инструкции. Перевод сейчас выполняется вручную |

[Быстрый старт админки](getting-started.md) · [Настройка кластерной миграции](../proadmin/migration/README.md#кластерный-pilot-server)

## Внешние сервисы

- **Pilot.** Если сервер уже есть, для веб-админки выберите роль `admin` и задайте адреса Pilot, доступные из контейнера. Роли `prod`, `test` и `stage` разворачивают свои контуры.
- **Git.** Используйте свой GitLab или включите роль `gitlab`. Подключение GitHub.com доступно для публикации типов на тест. [Поддержка Git-хостинга](git-hosting.md).
- **PostgreSQL.** Для нового контура можно использовать существующий PostgreSQL. При чистой установке задайте `<КОНТУР>_EXTERNAL_PG_HOST`, `<КОНТУР>_EXTERNAL_PG_PORT`, `<КОНТУР>_EXTERNAL_PG_DATABASE` и `<КОНТУР>_PILOT_PG_PASSWORD`. Подготовьте базу и роль `pilotuser` с правами владельца. Установщик проверит подключение и пропустит свой PostgreSQL для этого контура.
- **S3.** При чистой установке задайте `<КОНТУР>_EXTERNAL_S3_URL`, `<КОНТУР>_EXTERNAL_S3_BUCKET`, `<КОНТУР>_S3_ACCESS_KEY` и `<КОНТУР>_S3_SECRET_KEY`. Установщик проверит доступ к существующему бакету и пропустит локальный RustFS. Укажите тот же архив при подключении базы в Pilot.
