Перенос стенда PilotProAdmin на другой компьютер

1. Распакуйте комплект на исходном Windows-компьютере, где работает Docker Desktop со всем стендом.
   Для полной копии нужны локальные GitLab, Grafana, Loki, Prometheus и три контура Pilot с PostgreSQL и RustFS.
   Если сервисы расположены на разных машинах или используют внешние базы или хранилища,
   понадобится собрать копии отдельно на соответствующих серверах.

2. Откройте PowerShell в распакованной папке. Укажите каталог на локальном диске NTFS с достаточным местом:

   .\prepare-transfer.ps1 -OutputDirectory 'D:\PilotTransfer'

   Папку стенда скрипт находит сам по контейнеру postgres-prod. Если не нашёл, укажите папку установки вручную:
   это папка, где лежат .env и docker-compose.yml (её создал install.ps1, обычно ...\PilotProAdmin-install).
   Можно указать и папку распакованного релиза выше неё - скрипт возьмёт вложенную.

   .\prepare-transfer.ps1 -OutputDirectory 'D:\PilotTransfer' -InstallDirectory 'C:\PilotProAdmin-install'

   Для раздельной раскладки укажите -StackDirectory с папкой стека, где лежат prod, test, stage и metrics.
   Если каталог данных раздельного стека отличается от C:\Ascon-Docker, передайте его через -DataRoot.
   Если PowerShell заблокировал загруженные файлы, после проверки комплекта выполните
   Get-ChildItem -File -Filter '*.ps1' | Unblock-File

3. После успешного завершения перенесите папку, которую скрипт напечатал в конце. В ней лежит manifest.json.
   Для одного файла добавьте -Archive. Скрипт дополнительно создаст TAR, для которого потребуется ещё место.
   Если переносите TAR, распакуйте его на новом компьютере в отдельную папку перед установкой.
   Бэкап содержит базы, пароли и секреты GitLab. Передавайте его только доверенным получателям и храните с ограниченным доступом.
   На время окончательного переноса остановите изменения данных в исходных приложениях.
   Скрипт снимает копии отдельных сервисов последовательно, поэтому изменения во время работы могут попасть лишь в часть копий.

4. На новой машине распакуйте релизный lite.zip. Укажите папку с manifest.json и новый каталог установки:

   .\install.ps1 -Backup 'D:\PilotTransfer\snapshot' -InstallDirectory 'D:\PilotProAdmin'

   В копию входят данные и конфигурация. Образы Docker установщик получит отдельно.
   Лицензии Pilot проверьте после переноса на новое оборудование.

Ежедневная резервная копия

   Тот же комплект снимает плановые копии. Оставьте распакованную папку в постоянном месте и зарегистрируйте задание:

   .\register-task.ps1 -InstallDirectory 'D:\PilotProAdmin\PilotProAdmin-install' -Root 'E:\Backups' -KeepDays 14

   Задание «PilotProAdmin Backup» каждый день в 03:00 (ключ -At) запускает backup.ps1: копия в <Root>\<дата_время>,
   старше KeepDays дней удаляются, последняя удачная остаётся. Итог - <Root>\last-backup.json.
   Задание работает, пока пользователь вошёл в Windows (так работает Docker Desktop). Прежнее задание «CICD Backup»
   скрипт удаляет. Проверка: Start-ScheduledTask -TaskName 'PilotProAdmin Backup', затем last-backup.json.
   Копию из такого каталога тоже можно передать install.ps1 -Backup.
   Задание регистрируется только для полного стенда на одной машине (локальные GitLab, статистика, prod, test, stage
   со своими PostgreSQL и RustFS). Если что-то подключено извне, скрипт откажется и назовёт причину.
