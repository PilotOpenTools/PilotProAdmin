CI/CD для Pilot: от ветки в GitLab до сервера

Единый конвейер для автоматизаций, отчётов, клиентских и серверных модулей и типов. Три контура Pilot, проверки в CI, выкладка через веб-админку, статистика и логи в Grafana.

Как это устроено

Разработчик работает в GitLab. Админка забирает проверенный результат и записывает его на нужный контур. Grafana наблюдает за всеми контурами.

Единый путь изменения

Разработчик работает только с ветками. Запись на серверы Pilot делает админка - после успешного pipeline, а выкладка из CI подтверждается токеном задания и ключом контура.

  1. Ветка задачиправка в GitLab
  2. Проверки CIверсия, сборка, линтер
  3. Теставтоматически из dev
  4. Стейджиз release/X.Y.Z
  5. Продиз main с тегом

Хотфиксы идут отдельной веткой и возвращаются в dev. Записи из CHANGELOG попадают в описание версии в Pilot. Путь зависит от вида содержимого и настроек: у отчётов стейджа по умолчанию нет, у автоматизаций тест и стейдж можно объединить, а если адрес стейджа не задан, перенос идёт из dev в прод.

Что можно выкладывать

Для каждого вида содержимого - свой репозиторий, свои проверки и общая схема веток от задачи до прода.

Настройки

Серверные настройки

Раздел «Серверы» в админке задаёт настройки для каждого контура отдельно.

Защита на каждом шаге

Ошибку проще остановить до сервера, чем откатывать после. Гейты стоят и в GitLab, и в самой админке.

  1. Защита ветокdev, main и release/*
  2. Версияне забыта и не дублируется
  3. Сборка и линтерформат и структура
  4. Библиотекиправила для DLL
  5. Правароль в GitLab
  6. Зелёный пайплайниначе записи нет
  • Без зелёного пайплайна не публикуется ни автоматизация, ни отчёт, ни модуль.
  • Ревью по желанию. Слияние в тест можно потребовать только после одобрения не автором.
  • Общие проверки подключаются к репозиториям автоматизаций и отчётов одной настройкой.
  • Права. Ниже роли Developer в GitLab админка работает только на чтение; настройки, миграция и серверы доступны только администратору прода.
  • Ключи выкладки из CI. Свой ключ на каждый контур плюс токен задания; ключи стейджа и прода получают только задания защищённых веток.

Эксплуатация

Контуры

Три изолированных Pilot

Тест, стейдж и прод независимы: у каждого своя база, своё хранилище файлов и свои доступы. Пароли контуров при установке общие, отдельные задаются переменными с префиксами PROD_, TEST_, STAGE_.

Резервные копии

Копии по расписанию

Скрипты stack/backup для Windows копируют базы, файлы Pilot, GitLab и админку по заданию планировщика (оно работает, пока пользователь вошёл в систему). Копию можно проверить без восстановления, GitLab восстанавливается вручную. В установочный комплект эти скрипты не входят.

Установка

Комплект для другого сервера

Установка на одну машину или на несколько, на Linux и Windows. Для закрытого контура нужен комплект без интернета, его собирает поставщик. К комплекту прилагаются инструкции для администратора и службы ИБ.
