# Product

## Platform

web

## Users

Основной пользователь — администратор-интегратор Pilot (АСКОН Pilot-ICE / Pilot-BIM) в проектной организации. Он сам пишет автоматизации, отчёты, клиентские и серверные модули, настраивает типы и выкладывает всё это по контурам тест → стейдж → прод. Часто работает один: ревью в GitLab по умолчанию выключено, зелёный пайплайн обязателен всегда. Командный режим с ревью и раздельными учётками GitLab поддерживается настройкой.

## Product Purpose

PilotProAdmin — веб-админка, через которую изменения Pilot проходят путь от ветки в GitLab через проверки CI до серверов Pilot. Запись на сервер происходит только после успешного пайплайна. Рядом работает сервис PilotMigration: перенос баз и файловых архивов между контурами, импорт присланных баз, выгрузка в файлы. Цель — чтобы на прод попадало только проверенное, ветка всегда совпадала с сервером, а любой релиз можно было сравнить, объяснить (CHANGELOG, релизы) и откатить.

## Positioning

Открытый продукт для любых организаций на Pilot (GitHub: PilotOpenTools/PilotProAdmin, документация на GitHub Pages, релизы). Отличие — путь выкладки, привязанный к Git: ветка = сервер (`dev` → тест, `main` → прод), публикация только через CI с ключом контура, версии и CHANGELOG ведутся автоматически, контуры можно сравнить построчно. Стенд разворачивается целиком из установочного комплекта, в том числе для закрытого контура.

## Operating Context

- Вход: адрес сервера Pilot + логин/пароль Pilot, затем GitLab (OAuth или PAT). Права в группах GitLab ниже Developer — режим только чтения.
- Разделы: автоматизации, отчёты, клиентские модули, серверные модули, типы, настройки серверов, сравнение контуров, задания публикации, миграция, «Активные работы», настройки.
- Окружение: Docker Compose (порт 5300) или переносимая сборка для Windows; Pilot-Server (монолит или кластер), PostgreSQL, S3 (RustFS/MinIO), GitLab + Runner, Grafana/Prometheus/Loki для статистики и логов.
- Git-хостинг: полный CI/CD на GitLab; GitHub.com — только публикация типов на тест.
- Установочный комплект `stack/Install` передаётся на сервер целиком; есть вариант без интернета (`-Offline`).

## Capabilities and Constraints

- Интерфейс и все тексты только на русском; локализация не планируется.
- Стек: ASP.NET 8 Razor Pages (`proadmin/src/ProAdmin`), сторонние библиотеки лежат локально в `wwwroot/vendor`.
- Термины: контур (тест / стейдж / прод), выкладка, промоут, откат, ветка `dev`/`main`, автоматизация, отчёт (.repx), модуль, типы, задание публикации.
- У отчётов стейджа по умолчанию нет; у автоматизаций тест и стейдж можно объединить; без адреса стейджа перенос идёт из `dev` прямо в прод.
- Действия на проде необратимы для пользователей Pilot: изменения уходят в открытые клиенты.

## Product Principles

1. Сервер всегда равен ветке: ничего не попадает в Pilot в обход Git и CI.
2. Прод — особый контур: опасные действия видны, подтверждаются и ограничены правами.
3. Каждое изменение объяснимо: версия, CHANGELOG, сравнение, откат.
4. Один админ должен справляться в одиночку, команда — без перенастройки продукта.
5. Работает в закрытом контуре так же, как с интернетом.

## Accessibility & Inclusion

Доступность обязательна. Конкретный стандарт пока не выбран (открытое решение; разумная цель — WCAG 2.2 AA): полная работа с клавиатуры, контраст, состояния не только цветом (особенно маркировка контуров тест/стейдж/прод).
